## 失败、根因与修复

1. 历史综述 Run 被引文校验拒绝。根因是模型生成了超出 chunk 完整边界的摘录；修复了不完整 chunk 尾部裁剪、截断引文检查和有限修复，并保留失败记录用于回归。
2. 真实模型曾返回无效决策 Tool Call。修复是在服务端已验证的来源范围内，按未读来源顺序执行保守回退；不会绕过文件范围、权限或引用校验。
3. 首次新卷恢复在数据库 ready 前调用 `pg_restore`。恢复流程增加健康等待后通过，第一次失败继续记录在证据中。
4. 冻结复核的第一次只读计数命令误用镜像默认 `postgres` 角色；按 Compose 合同改用 `copilot` 角色后核对为 8 个迁移、3 个 Run、9 个 File、30 个 TraceSpan。该错误未修改产品数据。

## 证据边界与剩余风险

- GUI 主流程来自用户辅助人工观察；Codex 自动浏览器受本机 URL 策略阻止，未记录为自动 GUI 通过。
- 12 个 fixed tasks、3 个模型对照和 3 个容器任务是本机小样本，不能外推生产成功率。
- 费用目前只有 token 与时延，供应商未返回账单金额。
- owner 隔离测试覆盖已实现入口，不等同于全面安全审计或多人产品验收。
- 空闲资源采样不代表 2 核 4 GB 服务器的峰值容量。
- HTTPS、域名、反向代理后的 SSE、服务器重启、定时备份和服务器恢复属于 M8。
